# Localization Development

## Translation resources

Translations live in [en.json](../src/i18n/messages/en.json) and [zh-CN.json](../src/i18n/messages/zh-CN.json). English defines the message keys and provides the fallback for missing translations. Keep keys and named parameters consistent across languages. Name keys after their meaning, such as `article.intro.architecture` or `help.logits.embedding`, so they remain useful when sections are reordered.

In Svelte components, import `t` from `~/i18n` and use stable message keys such as `$t('ui.vector', { dimension: 768 })`. Preserve model prompts, generated tokens, formulas, numerical values, and code examples when translating surrounding text.

## Rendering translated content

Use ordinary escaped text for plain labels and headings. Render formatted tutorial and article content through [RichText.svelte](../src/i18n/RichText.svelte), which accepts a translation key only.

Rich text is trusted HTML bundled with the application. Keep its reference links and formatting intact, and do not insert user input into it. The translation tests allow only static formatting elements, known attributes, and HTTPS links.

## Adding a language

1. Add a dictionary under `src/i18n/messages/` with every key and named parameter from the English dictionary.
2. Add its code, display label, and browser language matching pattern to `supportedLocales` in [locale.js](../src/i18n/locale.js). The locale type, validation, language selector options, and dictionary tests derive from this list.
3. Import the dictionary and register it in the typed `messages` map in [index.ts](../src/i18n/index.ts).
4. Add browser language matching cases to [i18n.test.mjs](../tests/i18n.test.mjs) as needed. Dictionary coverage, references, and rich-text checks automatically include every registered language.

## Validation

Run these commands from the repository root:

```bash
npm run test:i18n
npm run build
npm run check
```

The localization tests check language selection, saved preference initialization and persistence, behavior when browser storage is unavailable, interpolation, dictionary coverage, all 20 tutorial lessons, reference links, and rich-text safety. The inherited codebase currently has TypeScript/Svelte diagnostics; compare `npm run check` results with the upstream baseline when reviewing localization changes.

In the browser, switch languages and confirm that the interface, tooltips, tutorial, and article update while the current input, model parameters, and tutorial position are preserved.
